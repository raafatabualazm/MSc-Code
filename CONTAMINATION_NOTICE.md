# Evaluation Contamination Notice

Date: 2026-07-10

## Finding

An artifact audit found that the historical local causal-decoder prompt builder
copied up to ten `candidate(...)` assertion lines from each benchmark row's
`tests` field into the policy prompt. Those assertions include concrete inputs
and expected outputs. The same `tests` field was then appended to generated code
by the pass@k evaluator. Consequently, the archived local 154-task functional
candidate pools are test-informed and are not valid hidden-test pass@k results.

The prompt-budget code preserved this fixed prompt prefix while truncating
assembly, so the scoring-test examples could survive when binary evidence did
not. This affects the interpretation of local pass@k, pass-set compile@k, GRPO,
RS-SFT/repair, reranking, and multi-arm union results derived from those pools.
The deployable reranker did not read tests directly, but its candidate inputs
were already test-informed.

## Scope

- The 1,195-row `dart_all_cfg_clean.jsonl` SFT corpus has no `tests` field. The
  ordinary SFT stage is therefore not contaminated by this specific prompt bug.
- The separate 126-row legacy CodeBLEU/compile corpus also has no scoring-test
  field. Its generation is not affected by this specific leak, although old
  control-path and provenance limitations still apply.
- Frontier-model pools were generated by separate prompt builders that did not
  include the benchmark tests. Their absolute results remain useful, but the
  historical local/frontier comparison was not information-matched.
- Historical run summaries do not pin a prompt hash, source commit, dataset
  hash, or immutable base-model revision. File timestamps are not sufficient
  proof that any archived local functional pool predates the leaking builder.
  All such pools are therefore treated as contaminated.

## GRPO Split Diagnostic

The archived binary-GRPO full-set pass@10 of 0.1818 mixes its 77 training tasks
with 77 held-out tasks. Recomputed from the archived candidate CSV:

| Split | pass@1 | pass@5 | pass@10 | Any-pass tasks |
|---|---:|---:|---:|---:|
| RL train half | 0.0455 | 0.1480 | 0.2078 | 16/77 |
| Held-out half | 0.0364 | 0.1081 | 0.1558 | 12/77 |

These remain contaminated diagnostics because the policy prompt exposed each
row's scoring assertions. They are not clean generalization results.

## Corrections Implemented

1. `build_decoder_prompt` now excludes `tests` by default. Test hints require an
   explicit Python-only oracle flag and are labelled as oracle diagnostics.
2. The inference path aborts if a test-hint marker reaches a policy prompt.
3. Prompt schema `antigravity-v2-no-test-hints` is recorded in provenance.
4. Training and inference now record dataset, checkpoint, output, and source
   SHA-256 hashes; Git state; seed; runtime; graph environment; and requested
   and resolved model revisions.
5. Task 160's benchmark exception is keyed by stable task ID and therefore
   applies identically to local and frontier prediction schemas.
6. The SFT corpus is split by normalized-source groups (1,081 train / 114
   validation), preventing its 188 duplicate rows from crossing the split.
7. GRPO has physically separate 77-row train and held-out JSONL files.
8. Controlled topology ablations now keep block encoding and prefix capacity
   fixed while selecting full, no-edge, shuffled, CFG-only, or DFG-only edges;
   a separate switch bypasses GINE while preserving global block attention and
   learned prefix pooling.

Integrity reports are under `results/protocol_audit/`. The clean multi-seed run
driver is `scripts/run_clean_confirmatory_x86.sh`.

## Publication Status

Historical local functional tables and the 17-arm union must not be submitted as
clean performance evidence. The paper requires a leakage-free rerun before an
A/A* submission. Until then, the frontier pools, architecture implementation,
legacy no-test corpus diagnostics, and protocol audit are retained as artifacts;
the contaminated local functional numbers are historical diagnostics only.
