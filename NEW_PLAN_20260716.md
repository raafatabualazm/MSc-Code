# Neural Decompilation — Failure Analysis & Forward Plan (2026-07-16)

Status: post-v3 synthesis. Written after the signature-scrubbed v3 experiment
completed and verified. This document supersedes the ad-hoc "decomposition arms"
notes; it records **why the current pipeline plateaus** and **the one staged
recipe** to try next, with pre-registered kill switches so the spend is bounded.

Guiding constraint (from the user): **no million-architecture ablations.** Every
step below is data or objective work on the *frozen* graph-prefix architecture.
The single architecture fork in the whole plan is "assembly text in the decoder
prompt: yes/no," and it is run as a controlled 2-arm comparison, not a sweep.

---

## 1. What we actually established (evidence, not opinion)

### 1.1 The v3 signature-scrub result (verified: 71/72 manifest hashes local, all integrity gates PASS)

Frozen Regions16 checkpoint, 154-task HumanEval-Dart eval, aligned-JIT metrics,
one scoring stack (pinned Dart 3.11.5 + patched `Crash when compiling` classifier):

| Arm | pass@1 | pass@10 | compile@1 | compile@5 | compiled cands |
|---|---:|---:|---:|---:|---:|
| comparator (semantic signature) | 17.66% | 27.27% | 77.08% | 93.80% | 1187/1540 |
| neutral_exact (typed `fn0` sig) | 0.71% | 4.55% | **84.61%** | **97.39%** | **1303/1540** |
| name_only (`fn0` only) | 0.00% | 0.00% | 3.18% | 11.77% | 49/1540 |

Reading:
- **Types/arity carry the compile signal.** With an opaque typed signature the
  model emits a correctly-named, correctly-typed, caller-compatible `fn0`
  1537/1540 times and compiles *better than the comparator* (+7.5 pp).
- **The semantic name carries the pass signal.** Remove it (keep everything
  else) and passing collapses: neutral_exact solves only 7 of the comparator's
  42 solved tasks (0 gains / 35 losses). ~83% of "solved" tasks were solvable
  **only** via name-keyed recall of the HumanEval solution from pretraining.
- **name_only** now *names* `fn0` correctly (1135/1540 define it — the matched
  contract works) but gets arity right only 272 times → almost never links
  against hidden callers → compiles ~3%.
- Standalone-AOT diagnostic (candidate-only, no tests): nameonly 4.6/20.8/37.0,
  neutralexact 53/91/98, comparator 51/81/88 @1/5/10. The scrubbed generations
  are not broken Dart, they are semantically wrong Dart.

### 1.2 The clean-study / interaction findings (prior, still standing)

- All topology knobs tie at n=154 (power-bound: McNemar MDE ≈ 6–11 net flips).
- **Permuted-prefix cost = −0.013 (p=0.5):** ~70% of the prefix benefit is
  content-agnostic mode-switching; the decoder barely reads prefix *content*.
- **Frozen-encoder** drops compile@1 0.78→0.48, pass@1 0.16→0.10: block-encoder
  content adaptation is load-bearing; topology is not.
- GPT-5.5 on the same 154 tasks: **0.71 pass@10 from assembly text**; adding
  serialized CFG to its prompt is null. The information is in the input.

### 1.3 The SFT-corpus correction (important honesty fix)

The 770-row SFT corpus (`dart_all_graphv2_train.jsonl`) has **0 signature
fields, 0 test fields**; 741/770 rows are named `main`. The comparator's
exact-signature prompt was therefore itself off-distribution. So the frozen
eval numbers were mostly **pretraining recognition unlocked at eval time**, not
a learned skill. All scrubbed evals are inference-contract ablations on a frozen
checkpoint, not in-distribution robustness estimates.

### 1.4 ARM64 (correcting an earlier mistaken claim in conversation)

ARM64 was **not** the 770-row test-less x86 corpus. Provenance (pod
`arm64v21_s42` run):
- Trained on **`flutter_train_graphv2.jsonl` = 1,371 functions, all with tests**;
  eval `flutter_eval_graphv2.jsonl` = 343, all with tests (1,371+343 = the 1,714
  Flutter pool).
- Result: **pass@10 ≈ 5.5% (19/343), pass@1 2.1%, compile@1 52.9%**, with a
  **total cliff: 0/168 solved at ≥200 instructions**, and even the 5.5% is
  signature-scaffolded (eval shows the semantic signature).

**The load-bearing point:** on ARM64 the ~1,700 test-carrying functions were
used only to *score* the eval. Tests were **never the training objective** —
training was cross-entropy on reference source (+ at most binary GRPO). So ARM64
already refutes "more test-carrying data fixes it": data volume + test
*availability* is necessary but **demonstrably not sufficient**. The untested
lever is using the tests as the **training signal**.

## 2. Root cause (single thesis)

**The binding variable is the training objective, not the input channel and not
the corpus size.** Next-token cross-entropy on the reference source pays
overwhelmingly for surface tokens; a binary GRPO reward had no gradient (62.5%
degenerate all-zero-reward groups). Nothing in any run ever paid specifically
for *execution behaviour*, so no channel and no data volume delivered semantics.

Three independent measurements agree:
- **SANER** (text, 4B, ~1.2k pairs): learns idiom/syntax fine (71.3 CodeBLEU).
- **TOSEM** (HumanEval-Dart metric study): sequence-only SFT lifts CodeBLEU /
  compile@k while pass@k stays flat or regresses.
- **v3 + ARM64**: graph-prefix and text fail *identically* — surface up,
  semantics ≈ 0 without name-keyed recall; more data (ARM64's 1,371) inert.

Two **separable** failure modes, which must not be conflated:
- **(A) Low semantic recovery on tractable (short/medium) functions** — an
  *objective* problem. Targetable. GPT-5.5's 0.71 says the ceiling is high.
- **(B) The ≥200-instruction cliff** — a *capacity/representation* problem.
  4–64 prefix vectors summarising 200+ instructions is a bottleneck. **More data
  and better reward will NOT fix this.** Needs length curriculum + chunked /
  hierarchical decoding, and may not be solvable at 8B at all.

## 3. Representation decision (made — not a sweep)

**Do NOT grow the prefix to 1024/2048 vectors.** Rationale, from our own data:
- 1024 soft vectors cost exactly the KV/attention budget of 1024 text tokens,
  but arrive in a space the decoder must *learn* from ~2k pairs, forfeiting
  text's one advantage (native pretrained comprehension). Large resamplers work
  in VLMs because they see 10^8 pairs.
- The permuted-prefix null shows the decoder doesn't read 64 vectors' content
  from 770 rows; 1024 makes the reading problem strictly harder at the same data
  scale.

**Committed representation: compact structured *text*, ≤ ~3–4k token budget, in
the decoder's native space.** Per function:
- v3-style neutral typed contract (~100 tok).
- **Evidence sheet** (~300 tok): strings, numeric constants, callees/stubs,
  arity/stack facts — all regex-extractable from the GDB dump today.
- **Cleaned + relabelled assembly** for functions ≤ ~150 instructions
  (~1.5–2.5k tok): existing `GRAPH_PROMPT_CLEAN_ASM` (−25%) + ReF-style
  jump-address→symbolic-label rewriting (the one decomposable input experiment
  already flagged in prior notes).
- Keep the existing 64-vector prefix as an optional mode-switch (or drop it).
  **Do not enlarge it.**

The "long text confuses an 8B" concern is handled by construction: the budget is
capped, prompt length is a config choice (Qwen3-8B is 32k-native; the 2048 cap
was an artefact of the truncation-bug era), and Phase 1 trains only below the
cliff where recovery is possible anyway.

## 4. Forcing the decoder to USE the vectors (if the latent channel is kept)

The prefix is ignored for two separable reasons; address both or neither works:
1. **Shortcut channels** — historically the text prompt carried name/signature
   so the loss never needed the prefix. Neutral `fn0` contracts fix this: with
   identical text across tasks, the prefix is the *only* task discriminator.
2. **Teacher-forcing leak (the subtle one)** — under CE, after ~20 gold tokens
   the remaining reference tokens are predictable from the emitted target
   itself, so prefix-reading gradient concentrates on the opening and then
   vanishes. Consistent with the permuted-prefix null.

Interventions, cheapest first:
- **Facts-first targets, no assembly text in prompt** (`ASSEMBLY_MODE=none`):
  first ~50 target tokens = `FACTS: constants/calls/arity/io-pairs`, verifiable
  and task-specific, predictable *only* from the vectors, before any
  teacher-forced self-conditioning accumulates. CE on those tokens *is* a
  prefix-reading loss — pure data change.
- **Sequence-level objectives** (RS-SFT, dense GRPO): train on free-running
  generations, so gold-continuation self-conditioning can't be exploited; a
  reward that varies with the binary under a constant text prompt is a gradient
  that flows *only* through prefix use. Same intervention as the recipe below.
- **Modality dropout** (hybrid input only): mask assembly text on a fraction of
  batches, anneal prefix-heavy. One hyperparameter.
- **Contrastive encoder head (only optional module):** InfoNCE matching pooled
  prefix ↔ its own facts/source vs in-batch negatives — guarantees the vectors
  *contain* discriminative content (separate failure point from the decoder
  reading it). A head, not an architecture change.
- **Gauge:** track the **permuted-prefix delta** per checkpoint (one extra eval
  pass). Today −0.013 (nothing read). Success = cross-task permutation starts
  *destroying* facts-accuracy and pass@k. Turns "is it reading the vectors?"
  into a number.

## 5. The recipe (one path, staged, pre-registered kill switches)

No architecture ablations. Five training jobs total. Every checkpoint scored on
the **frozen v3 arms** (+ a length-stratified slice), so every delta is
attributable to the training signal.

**Phase 0 — data consolidation (CPU box, ~days).**
- Corpus taxonomy (measured 2026-07-16):
  - 1,727 unique synthetic functions **with `expect()` tests** (median 11
    asserts) — `synthetic_pool_graphv2` (note: `flutter_function_assembly_pool`
    overlaps it by 1,713; they are the *same* pool, not additive).
  - 1,371 Flutter-train (ARM64) functions with tests.
  - 1,006 unique `dart_all` functions (RosettaCode natural + old synthetic) with
    **0 tests** — disjoint from the synthetic pool (∩ = 0).
  - Grand unique union ≈ **2,733 functions.**
- Actions: (a) retire the 770-row test-less SFT corpus as the trainer input;
  (b) retrofit oracles for the *deterministic, pure, single-return* subset of
  the 1,006 naturals (fuzz/property inputs → execute reference → freeze
  input→output harness) — the naturals are the scarce real-world half worth the
  effort; (c) gate EVERY row on *reference passes its own tests* (benchmark refs
  only pass ~142/154 — same bar here); (d) dedup by normalized-source hash
  against BOTH frozen evals (154 + fresh_eval); (e) emit per row: compact-text
  input + neutral `fn0` contract + target = `FACTS:` block (constants/callees/
  arity from parser, 2–3 executed I/O pairs) then source; length-cap ≤150 instr
  for Phase 1.
- Structure = **one** unified train pool, **one** frozen 154 benchmark (never
  touched), fresh_eval as secondary generalization check. Not a single merged
  bag — that is the leakage that voided the July x86 ablation.

**Phase 1 — one SFT run** (LoRA, existing configs, ~hours). Facts-first targets,
neutral contracts. Baseline to beat on frozen v3 neutral_exact: **4.55% pass@10.**

**Phase 2 — RS-SFT, 2 rounds (the SFT×RL hybrid).**
- Per task: sample k=16 from current checkpoint → **compile gate** → **per-assert
  partial credit on the VISIBLE split** (hidden tests never touched) → keep best
  verified passer per task → next SFT mix, **50/50 with gold** (anti-collapse).
- **Compiler/assert messages fed back as CONTEXT for one repair attempt**;
  repaired passers are harvested too (`repair_loop_antigravity.py` implements the
  modes). This is the compiler-feedback loop.
- **Frontier-LLM critic = tie-break FILTER only**, among verifier-approved
  candidates; its pick enters training only if it compiles AND its FACTS block
  matches assembly-extracted facts. **Never a reward term** — unverifiable dense
  signals are exactly the family that destabilised the logprob-distillation
  attempt (`dual_distil*`: cross-tokenizer char-span pseudo-probabilities).
- **KILL SWITCH:** round 1 must move v3 neutral_exact pass@10 by **≥ +6 pp**
  over 4.55% (McNemar MDE at n=154). Below that = noise → STOP, thesis unsupported.

**Phase 3 — optional single VeRPO-style polish** (only if Phase 2 paid). Dense
per-assert verifiable reward (VeRPO *is* the dense-partial-credit formulation;
11-assert tasks are its granularity sweet spot; reported to cut degenerate-group
collapse ~60–70%→<25%). Stability fixes for what broke last time: drop
zero-variance groups, KL-anchor to the RS-SFT checkpoint, length-normalised
logprobs, grad-clip 1.0, **bf16 not 4-bit**. Do NOT lead with GRPO; it is a
polish on an already-improved policy.

## 6. The cheap discriminating experiment (do THIS first)

Before any flagship spend, run Phases 1–2 on a **length-controlled slice**
(≤120-instruction Flutter/synthetic functions) and evaluate on the matched-length
eval slice:
- If RS-SFT + dense reward **moves short-function pass@k** → the objective thesis
  (failure mode A) holds → scale to the full recipe.
- If it **doesn't move even on short functions** → the problem is deeper than the
  training signal → stop and reassess before spending on data/RL at scale.

This falsifies (or confirms) the core thesis for a few GPU-days instead of a
flagship budget, and isolates failure-mode A (objective, targetable) from
failure-mode B (the ≥200-instr capacity cliff, a separate research risk needing
hierarchical decoding — do not let the flagship depend on it unproven).

---

## 7. What NOT to do

- Do not grow the prefix to 1024/2048 vectors (§3).
- Do not merge all corpora into one bag (§5 Phase 0e — leakage).
- Do not turn any LLM/critic "why it failed" text into a reward gradient (§5
  Phase 2 — unverifiable dense signal, known-unstable).
- Do not run architecture ablations; the architecture is frozen for this plan.
- Do not claim the ≥200-instruction cliff is a data/reward problem — it is
  capacity/representation (§2 failure mode B).

## 8. Paper framing (bonus, falls out of the above)

Unified narrative, three-point evidence chain: **any input channel teaches an 8B
syntax and interface adherence; no channel teaches semantics until the objective
pays for execution behaviour.** SANER (text learns surface) → TOSEM (SFT lifts
surface, not pass@k) → v3+ARM64 (graph-prefix and text fail identically; name-
keyed recall explains the apparent x86 signal; 1,371 test-carrying ARM64
functions inert under a surface objective). Paper B decides text-vs-vector by
running the single §4 fork, not a sweep.
